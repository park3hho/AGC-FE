# 수입식품 구매대행 수입신고

> 구매대행 식품은 주문마다 통관 전에 유니패스로 수입신고한다. 빠뜨리면 시정명령 → 영업정지.

## 1. 원칙 (반드시)

- 고객 주문으로 들여오는 식품은 **주문(받는 사람)마다 1건씩** 유니패스 "인터넷 구매대행 수입식품등의 수입신고서"를 낸다.
- **통관 전에** 내야 한다. 통관된 뒤에는 신고할 방법이 없다(시행규칙 제27조 제2항).
- **B/L(운송장) 1개 = 신고서 1장.** 묶음 집운이라도 집운 상세에 국제/국내 송장이 상자별로 여러 개 나오면 송장마다 따로 신고하고, 그 상자에 든 품목만 넣는다(11-14 OR-261111-0003~5: 송장 3개인데 대표 1개로만 내서 2건 추가 신고). 송장이 1개면(11-10 성남 오* 5상자처럼) 신고서 1장에 품목 여러 줄.
- 기본은 **사전신고**: 집운이 출고되고 B/L(운송장)이 나오면 **바로** 낸다(관세청 화물 조회에 안 잡혀도 됨). 사전신고를 고르면 선(기)명 '사전신고' · 보관창고 00000000 · 입항일자·반입일자 9999-12-31 이 자동으로 들어가서 B/L 만 있으면 된다. 이미 입항했으면 본신고(선명·창고·입항일은 화물진행정보 값).
- 고객 통관부호로 통관해도, 판매자가 직접 보내도 구매대행이면 신고 대상이다(대법원 2021도2046).
- 수수료 없음, 첨부 서류 없음. 처리기간: 서류검사 2일, 정밀검사 10일.

## 2. 안 하면

- 시행규칙 별표 13 제15호: 1차 시정명령, 2차 영업정지 7일, 3차 영업정지 15일.
- 처분이 한 번 나면 그 이전의 같은 위반은 다시 처분하지 않는다(별표 13 일반기준 6).
- 2026-11-06 이전에 통관된 고객 주문(차파이·미닛메이드·헤이티 등)은 신고하지 못했다. 첫 신고는 차지 OR-261101-0001.

## 3. 유니패스 들어가기

1. 유니패스 로그인(HQ 계정 #5) → 통관단일창구 → 요건신청 → 신청서작성.
2. 공동인증서 창: 사업자 인증서 "박찬호(이도)(IDO)" 선택, 비밀번호는 HQ #7.
3. 목록 8번 "인터넷 구매대행 수입식품등의 수입신고서" 클릭 → 반입차단 원료 안내창 [확인].
4. "신청서작성 권한이 없습니다"가 뜨면: MY메뉴 › 개인정보수정 › 부호및서비스신청에서 "요건신청(통관단일창구)" 체크 → 완료 → **로그아웃 후 다시 로그인**. (2026-11-06에 켜 둠)

## 5. 끝나고

- AGC **판매 › 수입신고**(/import-declarations, API `/import-declarations`)에 기록한다 — 신고서 1장 = 1건, 같은 B/L 로 온 같은 고객 주문은 order_ids 로 같이. 칸: decl_no(WCANB-…) · kind(pre/main) · status(sent→accepted→approved, fix·rejected) · bl_no · vessel · arrival_date · items[{name_en, maker_en, country, qty, unit}] · seller_site · shipper_site. 신고서 화면 캡처/PDF 는 주문 증빙 kind `import_decl` 로 올린다.
- 낼 것 목록: `GET /import-declarations/pending` (집운 출고 · B/L · 통관 전 · 그 B/L 신고 없음). 주문 목록 `progress.decl_missing` 이면 홈 할 일 '수입신고'.
- 보완 요청이 오면 처리현황에서 내용 확인 후 같은 신고서로 보완 전송.
- 정밀검사 대상이 되면 고객에게 알리고 동의를 받는다(샘플은 식약처가 창고에서 직접 가져감).

## 7. 에이전트 작업 요령 (2026-11-12 첫 일괄 신고 5건에서 확인)

- 유니패스 alert/confirm 은 브라우저 대화상자 이벤트로 안 잡힌다 → 버튼 누르기 전에 `window.alert`·`window.confirm` 을 덮어써서 메시지를 모은다(confirm 은 true). 오류검증 성공 문구: "오류검증 결과 오류가 존재하지 않습니다." · 임시저장: "임시 저장되었습니다." · 전송: "신고서가 제출되었습니다."
- 칸은 id 로 채운다: `CSW0101005S_` + blNo · impOwrNm(수하인 성명) · impOwrTelno · persEcm(통관부호) · dclrTmngTpcd(신고구분 A본/B사전) · dclrFdmcIttCd(신고기관) · dclrAgntTelno · dclrAgntElcmSiteUrl(신고인 사이트) · shprElcmSiteUrl(송하인 사이트) · mnfuNm · mnfuInfoUrl(제품 URL, 필수) · mnfcCoConm · mnfcCoCntyCd/mnfcCoCntyNm(CN/중국 — 값만 넣어도 됨) · dclrTqty · reqRqstNo3(채번된 번호).
- 신고인은 영업등록번호 칸이 읽기 전용 → 옆 [검색] 팝업(식약 국내업체 조회)에서 허가번호 20260028639 조회 → '이도식품' 클릭. 팝업 탭은 REPL 호출이 끝나야 탭 목록에 잡힌다 → [검색] 누르는 호출과 팝업 처리 호출을 나눈다.
- 전송 뒤 화면이 처리현황으로 바뀐다. 거기서 바로 '신청서작성'을 누르면 신고서 화면이 두 번 겹쳐 로드돼(같은 id 2개) 값이 엉킬 수 있다 → 매번 첫 화면(index.do)부터 통관단일창구 › 신청서작성 › 신고서 링크로 새로 연다. 겹쳤으면 쓰던 번호는 버리고(임시저장 전이면 그냥 둠) 새로 연다.
- 공동인증서 창은 로그인 뒤 첫 신청서작성 때 한 번 뜬다(사업자 '박찬호(이도)(IDO)', 비번 HQ #7).
- 처리현황 기본 조회는 오늘 날짜만 — 자정을 넘기면 어제 건은 날짜를 바꿔 본다.
- 품목 줄: 같은 상품 여러 상자는 줄 하나에 총수량. 제품명 예: `NONGFU SPRING ORIENTAL LEAF BLACK OOLONG TEA 500ML 15 BOTTLES` · `NONGFU SPRING CHAPAI GREEN GRAPE OOLONG TEA 500ML 15 BOTTLES`. 신고인 사이트: 네이버 https://smartstore.naver.com/eidofood, 쿠팡 https://shop.coupang.com/A01774978.

## 8. 오류통보가 오면 (2026-11-12 6건 모두 오류통보 — 사유: 티몰 URL)

- 처리현황 › 신청번호 › 처리이력 '오류통보' 링크 → 팝업 '오류내역' 은 **textarea 안에 글이 있다**(innerText 로는 비어 보임 → `textarea.value` 로 읽는다).
- 고쳐서 다시 낼 때: 오류통보 건은 접수 전이라 **새 원본으로 다시 낸다**(새 신고서 열기 → [채번] → 전부 다시 입력). [불러오기]로 불러온 신고서는 [채번]이 안 먹고 전송구분이 '원본'에 잠겨 있어 쓰지 않는다.
- AGC: 옛 기록은 status `rejected` + result 에 사유, 새 번호로 새 기록(memo 에 옛 번호).
- 통관된 뒤 오류통보를 알게 되면 다시 낼 수 없다(00001C CHAGEE: 11-06 17:24 오류통보, 17:33 통관). 그래서 **오류통보는 매 회차 처리현황에서 확인**한다.
