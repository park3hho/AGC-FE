# AGC 모바일 화면 설계

> 휴대폰(≤ 768px)에서 AGC 를 어떻게 보여 줄지 — 화면 33개 점검 결과와 화면별 설계, 만드는 순서. 2026-10-30 초안, 아직 구현 전.

목업(그림): `AGC/FE/docs/mobile-mockups.html` — M1~M9. 이 문서의 화면 번호(M1…)가 그 그림이다.
기존 규칙(데스크탑 포함)은 `FE/DESIGN.md` §4. 이 문서는 그 위에 **모바일에서 달라지는 것만** 정한다.

---

## 1. 휴대폰으로 하는 일 — 우선순위

모바일 화면은 "데스크탑 화면을 줄인 것"이 아니라 **폰에서 실제로 하는 일**에 맞춘다.

| 등급 | 폰에서 하는 일 | 화면 |
|---|---|---|
| **A · 매일** | 새 주문 확인 · 발주확인 · 통관부호 불일치 대응 · 클레임 확인 | 홈 · 주문 |
| **A · 매일** | 타오바오 앱에서 산 직후 구매기록 적기 · 판매처 발송/입고 표시 · 집운 기록 | 구매 추가·수정 · 집운 추가·수정 |
| **A · 매일** | 상세페이지 검수 — 미리보기 보고 확인 · 다음 | 디자인 (제품) |
| **B · 가끔** | 제품·가격 보기, 판매가 한두 개 고치기, 환율 확인 | 제품조사 · 가격조사 · 가격 책정 · 상품 · 환율 |
| **B · 가끔** | 사업자번호·계좌·통관부호 **복사** | 회사 정보 |
| **C · 데스크탑에서** | 새 제품·가격조사 대량 입력, 상세페이지 본문 편집, 배송비 표, 주소 수정, API 키, 사용자 관리, 플레이북 | 해당 화면 — 모바일은 **보기 + 꼭 필요한 버튼만** |

원칙: A 등급은 폰에서 **처음부터 끝까지** 할 수 있어야 하고, C 등급은 폰에서 깨지지만 않으면 된다.

## 2. 지금 상태 점검 (2026-10-30, 375×667, 실제 사이트)

좋은 점: 33개 화면 모두 **페이지 전체 스크롤이 없고**, 대부분 목록이 행 목록 · 아래 탭 · 섹션 탭으로 이미 모바일 대응이 돼 있다.

고쳐야 할 것 (심한 순서):

| # | 화면 | 문제 | 고칠 것 |
|---|---|---|---|
| 1 | **주문 접수** | 주문을 고르면 목록이 사라지고(높이 0) 돌아갈 버튼이 없다. 금액·추적 기록이 위아래로 쌓여 둘 다 좁고, 발주확인 같은 할 일 버튼이 안 보인다. 추적 기록 머리 글자가 세로로 깨진다 | 목록 / 상세를 **다른 화면**으로 (M2 · M3) |
| 2 | **가격 책정 (제품)** | 쿠팡·네이버 나란히 표라서 **가로 스크롤**(화면 밖 요소 235개), 작은 입력칸 46개 | 판매처 탭 + 옵션 카드 (M6) |
| 3 | **타오바오 구매 추가 · 집운 추가** | 한 줄에 칸 3~4개가 들어가 라벨이 세 줄로 깨지고 입력칸이 잘린다(`예: 元`, `20[달력]`) | 한 줄 한 칸 폼 (M4) |
| 4 | **타오바오 구매기록** | 모바일인데 **표**(열 3개, 글자 잘림) · 상태 필터가 **알약 칩**(§4.2-9 위반) | 행 목록 + 필터 시트 (M7) |
| 5 | **회사 정보 › 기본 정보** | 분류 바로가기가 알약 칩 · 카드 상자 · 작은 버튼 28개(수정·삭제·복사) | 행 + 복사 + ⋯ 시트 (M8) |
| 6 | **디자인 (제품)** | 첫 탭이 편집이라 폰에서 할 일(미리보기 보고 확인)이 한 번 더 눌러야 나온다. S1~S6 탭이 두 줄로 접힌다 | 첫 탭 = 미리보기, 검수 모드 (M5) |
| 7 | 모든 화면 | 위쪽 바의 화면 이름과 화면 제목줄이 **같은 글자를 두 번**(예: 제품조사 / 제품조사) → 44px 낭비 | 모바일은 제목줄을 위쪽 바에 합친다 (§3.2) |
| 8 | 아래 탭 | 홈·제품·가격조사·가격 책정·더보기 — 매일 쓰는 **주문**이 더보기 안에 있다 | 홈·주문·디자인·제품·더보기 (§3.3) |
| 9 | 집운 기록 | 상태 드롭다운 글자가 잘림(`상태 전체 0`) | 필터 시트 |
| 10 | 플레이북 | 목록·본문이 위아래로 같이 보여 본문이 좁고 코드 줄이 가로로 넘친다 | 목록 → 본문 화면 이동, 코드 줄바꿈 |
| 11 | 출고지·반품지 · 판매처 | 본문 비상 스크롤(`.page-flat`)이 생김 — 규칙상 버그 | 섹션 탭으로 나누기 |
| 12 | 로그인 계정 · API 키 | 화면을 빠르게 옮겨 다닐 때 한 번 "불러오지 못했어요" · 로그인 화면으로 튕김 (데스크탑에서 다시 열면 정상, API 200) | 토큰 갱신이 겹칠 때의 문제로 보임 — 구현 때 재현 확인 |

## 3. 모바일 공통 규칙 (≤ 768px)

### 3.1 크기 기준
- 기준 화면 **375×667**(작은 폰) — 여기서 깨지지 않으면 큰 폰도 된다. 확인은 375×667 · 390×844 두 개.
- 지금 768px(틀)과 480px(한 화면 한 섹션) 두 기준이 섞여 있다 → **768px 하나로** 맞춘다. 태블릿 세로(768)도 모바일 틀.
- 높이는 `100dvh`, 아래쪽은 `env(safe-area-inset-bottom)` 만큼 띄운다 (아이폰 홈 막대).
- 글자: 본문 15px · 보조 13px · 작은 정보 12px(이보다 작게 쓰지 않는다). 숫자·코드는 `--font-num`.
- 누르는 것: 버튼 **44px** 이상(지금 규칙 40px → 44px로), 행 **56px** 이상, 글자 링크도 위아래 여백으로 44px 확보.

### 3.2 위쪽 바 = 화면 제목 (44px 한 줄)
- 모바일에서는 `PageHeader` 제목줄을 따로 그리지 않고 **위쪽 바에 합친다**: `[←] 화면 이름(또는 제품명) … [오른쪽 버튼 1개]`.
- 오른쪽 버튼은 그 화면의 대표 행동 하나 (`+ 추가`, `↻ 가져오기`, `✎`, `ⓘ`). 둘 이상이면 `⋯` → 아래 시트.
- 환율은 홈 · 더보기에서만 보인다 (지금은 모든 화면 위쪽 바에 있음 — 매번 볼 필요 없음).
- 설명 글(`sub`)은 모바일에서 숨긴다. 상태(검수 대기 등)는 화면 첫 줄에 점 + 글자로.
- 섹션 이름 보기 버튼은 개발자 모드에서만.

### 3.3 아래 탭 (56px)
- **홈 · 주문 · 디자인 · 제품 · 더보기** (지금: 홈 · 제품 · 가격조사 · 가격 책정 · 더보기)
  - 주문: 빨간 숫자 = 접수 단계 주문 + 새 클레임
  - 디자인: 주황 숫자 = 검수 대기 (99 넘으면 `99+`)
  - 제품: 제품조사 목록. 가격조사 · 가격 책정 · 상품은 제품 화면 안 바로가기 + 더보기
- `menuConst.js` 의 `tab: true` · `tabLabel` 만 바꾸면 된다 (사이드바·더보기는 그대로).

### 3.4 목록
- 표 금지 → **행 목록**(`ListItem`): 왼쪽 썸네일 44px 또는 마켓 표시 · 가운데 굵은 한 줄 + 보조 한 줄 · 오른쪽 상태(점 + 글자).
- 주문·구매처럼 "다음에 뭘 해야 하는지"가 있는 목록은 셋째 줄에 **다음 할 일**(파란 글자, 문제면 빨강).
- 위에 **검색 한 줄 + `필터` 버튼**(고른 필터 수 표시). 필터·정렬 드롭다운은 **아래 시트**(M7)로 모은다. 단계처럼 자주 바꾸는 것(접수/처리/완료)만 글자 탭으로 위에.
- 글자 탭은 **4개까지**, 넘치면 드롭다운. 가로로 미는 탭 금지.
- 페이지 넘김은 지금처럼 `Pager` (행 수는 `useFitRows`). 무한 스크롤은 쓰지 않는다 (페이지 스크롤 금지 규칙).
- 행을 누르면 상세 화면으로 이동. 목록 / 상세가 한 화면에 나란히 있는 데스크탑 구조(주문 접수)는 모바일에서 **두 화면**으로 나눈다.

### 3.5 상세 화면
- 맨 위 요약(사진·이름·상태 한 덩어리, 120px 이내) → 그 아래 글자 탭(최대 4개) → 탭 내용(이 부분만 스크롤).
- 할 일이 있으면 요약 바로 아래 **다음 할 일 상자**(M3) 하나만. 버튼은 아래 고정 줄에.
- 값 옆 **복사** 버튼 (받는 분 · 전화 · 주소 · 통관부호 · 주문번호 · 계좌). 전화번호는 누르면 전화, 링크는 새 창.

### 3.6 폼
- **한 줄에 한 칸**, 라벨은 칸 위. 단위·환산은 칸 안 오른쪽에 작게(`위안 ≈ 19,432원`).
- 키패드: 금액·무게 `inputmode="decimal"`, 번호 `inputmode="numeric"`, 전화 `tel`.
- 주문번호·운송장처럼 복사해 오는 값은 칸 안에 **붙여넣기** 버튼.
- 고를 것이 2~4개면 드롭다운 대신 **한 줄 버튼**(결제수단 · 운송 · 상태). 5개 이상만 드롭다운.
- 날짜·시각은 기본 "지금", 옆에 `지금` 버튼.
- 자주 안 쓰는 칸(실제 청구 원화, 메모, 증빙)은 **접어 둔다**(`펼치기 ⌄`).
- 저장 버튼은 아래 고정. 키보드가 올라오면 저장 줄을 키보드 위에 붙인다(`visualViewport`).
- 저장 안 하고 뒤로 가면 "버리고 나갈까요?" 확인.

### 3.7 아래 시트 (새 공통 부품)
- 필터 · 정렬 · `⋯` 메뉴(수정·삭제·원본 보기) · 짧은 확인(삭제 등)은 화면 아래에서 올라오는 시트.
- 모달(가운데 상자)은 모바일에서 쓰지 않는다 → 시트로.

### 3.8 그대로 두는 것
- 페이지 전체 스크롤 금지 · 섹션 하나만 스크롤 · 칸(pane) 배치 · 알약 금지 · 색은 토큰만 · 테마 2개(넷러너도 같은 배치).

## 4. 화면별 설계

표기: **[A/B/C]** = 1장 등급. "지금" = 점검 결과, "모바일" = 바꿀 모습.

### 4.1 공통 틀 — 위쪽 바 · 아래 탭 · 더보기 (M1 · M9)
- 위쪽 바 §3.2, 아래 탭 §3.3.
- **더보기**(M9): 아이콘 격자 → **한 줄 메뉴 목록**, 묶음(소싱 · 주문 처리 · 설정) 제목. 메뉴 옆에 작은 상태(가격 책정 대기 수, 환율 값). 맨 아래 `관리자 — 테마 · 개발자 모드 · 로그아웃` 한 줄 → 시트.
- 개발자 모드 메뉴(구매기록 · 집운 기록 · 플레이북)는 지금처럼 보라색.

### 4.2 홈 [A] (M1)
- 지금: 탭 4개(할 일 · 현황 숫자 · 진행 단계 · 최근 제품), 위에 가격조사 추가 · 제품 추가 버튼.
- 모바일: 탭 **할 일 · 현황 · 진행 단계** 3개(최근 제품은 제품 탭에 있음). 위 버튼 두 개는 빼고 `+`(위쪽 바) → 시트(제품 추가 · 가격조사 추가).
- 할 일은 **주문 처리 먼저**: ① 새 주문 발주확인 ② 타오바오 구매 기록하기 ③ 판매처 발송·입고 확인 ④ 집운 요청·국내 송장 ⑤ 클레임 ⑥ 상세페이지 검수 ⑦ 가격 책정 대기. 줄마다 큰 숫자 + 설명 + `›`, 누르면 그 목록을 필터 걸린 채로.
- 할 일 아래 "오늘" 요약 3줄(새 주문 · 클레임 · 마지막 수집).
- 필요한 BE: 홈 할 일에 주문 처리 항목이 아직 없으면 `/orders` 집계(단계별 · 다음 할 일별 건수)를 추가.

### 4.3 주문 [A] (M2 → M3)
가장 중요한 화면. 데스크탑의 "목록 | 상세" 한 화면을 모바일에서는 **주문 목록**(`/orders`)과 **주문 상세**(`/orders/:id`, 새 경로 — 데스크탑에서 열면 지금 화면에 그 주문을 골라 보여 줌)로 나눈다.

**주문 목록 (M2)**
- 위쪽 바: `주문` · 오른쪽 `↻ 가져오기`(누르면 세 마켓 수집, 끝나면 "새 주문 2건").
- 글자 탭: 접수 · 처리 · 완료 · 전체 (개수). 검색: 코드 · 마켓 주문번호 · 받는 분. 필터 시트: 마켓 · 통관부호 상태 · 클레임만.
- 행: 마켓 표시(N/C/S) · `OR-코드 · 상품명` · `받는 분 · ×수량 · 시각 · ●통관부호` · **다음 할 일**.
  - 다음 할 일 규칙(위에서 처음 맞는 것): 클레임 있음 → "클레임 처리"(빨강) · 통관부호 불일치/없음 → "고객에게 통관부호 확인"(빨강) · 발주확인 전 → "발주확인 보내기" · 구매기록 없음 → "타오바오 구매 기록" · 판매처 발송 전 → "판매처 발송 확인" · 입고 전 → "입고 확인" · 집운 요청 없음 → "집운 배송 요청" · 국내 송장 없음 → "국내 송장 넣기" · 자사몰이고 송장 있음 → "배송 완료 표시".
- 알림(새 주문·클레임 생김)은 목록 맨 위 한 줄 + 아래 탭 숫자.

**주문 상세 (M3)**
- 위쪽 바: `← OR-코드` · `⋯`(마켓 원본 · 통관부호 다시 검증 · 금액 증빙 올리기).
- 요약: 마켓 표시 · 상품명 · **진행 6칸**(접수 · 발주확인 · 구매 · 창고 · 국제 · 배송 — 데스크탑 11칸을 묶음). 클레임이면 빨간 줄 하나 추가.
- **다음 할 일 상자** — 목록과 같은 규칙, 한 문장 설명.
- 글자 탭: **주문 정보**(받는 분·전화·주소·통관부호 = 복사 버튼, 옵션·수량, 타오바오 링크) · **기록**(추적 기록, 한 줄 = 시각 · 단계 · 종류, 누르면 아래 시트로 내용·누가·출처) · **금액**(들어온 돈 · 나간 돈 · 이익, 지금 `OrderMoney` 그대로 세로) · **원본**(마켓 원본, 개발자 모드만).
- 아래 고정 버튼 = 다음 할 일 버튼: 발주확인 보내기 / 구매 기록하기(→ M4) / 집운 기록하기 / 배송 완료 표시. 옆 `⋯`.

### 4.4 타오바오 구매 추가 · 수정 [A] (M4)

- 모바일 순서 (위에서부터 한 줄 한 칸):

  2. 타오바오 주문번호 · 필수 (붙여넣기)
  3. 결제 위안 (decimal, 오른쪽에 원화 환산)
  4. 결제수단 한 줄 버튼: 카드 · 카카오페이 · 알리페이 · 기타

  6. 접는 칸 ①: 상품 링크 · 판매처 · 산 옵션·수량·단가 (주문에서 채워 오고 다를 때만 연다)

## 7. 정해 주셔야 할 것

1. **아래 탭 구성** — 홈 · 주문 · 디자인 · 제품 · 더보기 로 바꿔도 될지. (디자인 대신 상품, 또는 제품 대신 가격 책정도 가능)
2. **주문 상세 새 경로** `/orders/:id` — 데스크탑도 이 주소로 열 수 있게(링크 공유) 할지, 모바일 전용으로만 둘지.
3. **디자인 (제품) 모바일에서 편집 허용 범위** — 글만 고치기 허용(지금 안) / 아예 보기 + 확인 · 다음만.
4. 홈 할 일에 **주문 처리 항목**을 넣을지 (넣으려면 BE 집계 하나 추가).
5. 1단계(틀)부터 바로 구현을 시작할지.
